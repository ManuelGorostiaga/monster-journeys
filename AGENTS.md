# Monster Journeys — Agent Guidelines & Project Knowledge Base

## Project Overview
Monster Journeys is a single-page digital prototype for a tabletop board game inspired by *Sinnoh Journeys* and monster-catching card games. It supports 1 to 4 players (playable hotseat/solo for complete testing) directly in the browser.

## Architecture & Code Structure

The project uses a clean modular source structure compiled into a single production `index.html` file so that it works both as a standalone zero-dependency file and as a static web deployment.

### File Manifest
- `c:\Dev\monster-journeys\index.html`: Bundled output file (generated by `build.js`). Do not edit directly; modify the source files below and rebuild.
- `c:\Dev\monster-journeys\build.js`: Node.js build bundler. Inlines CSS and all JS modules into `index.html`.
- `c:\Dev\monster-journeys\test-suite.js`: Node.js automated test suite (12 test suites covering all core game logic). Run with `node c:\Dev\monster-journeys\test-suite.js`.
- `c:\Dev\monster-journeys\css\styles.css`: Styles for the board game UI, playing card proportions (5:7 ratio), layout, and modals.
- `c:\Dev\monster-journeys\js\data.js`: Database for characters, 40 monsters, attacks, 20 items, 23 locations (18 environment cards + 4 gym cities + 1 starting town), and weakness rules.
- `c:\Dev\monster-journeys\js\cardmap.js`: Interconnected Card Node system. Manages grid coordinates, adjacent slots, discovering new zones, and city placement.
- `c:\Dev\monster-journeys\js\combat.js`: 1v1 combat engine, attack dice rolling, weakness checks, monster switching penalty, item effects (e.g., Oran Berry at 0 HP), and post-combat healing/rewards.
- `c:\Dev\monster-journeys\js\tournament.js`: Grand Tournament brackets and final PvP tournament resolution when 3 of 4 gyms are beaten or at round 20.
- `c:\Dev\monster-journeys\js\game.js`: Core game loop, player management, turn state (movement & action), luck system, shop river, fast travel, gym expansion unlocks, and win conditions.
- `c:\Dev\monster-journeys\js\ui.js`: DOM rendering for card grid, player dashboard, codex compendium, river shop, search encounters, combat arena, and action controls.
- `c:\Dev\monster-journeys\js\sound.js`: Web Audio API procedural sound synthesizers (dice rolls, victory jingle, capture sounds, hits, button clicks).

## Core Game Rules & Mechanics

1. **Card Monsters**: Each monster card has HP, Speed, an element type, Weakness tag (`Weak +2`), capture tier requirement (1 to 4), and attack moves with base damage + dice rolls. Monsters do not evolve.
2. **Combat 1v1**: Turn options are either attack or switch monster. Switching absorbs incoming opponent damage without dealing damage that turn. Post-combat fully restores all monsters. Losing a combat still awards full prize money.
3. **Attack Rolls**: Dice rolls are simulated in the background. Logs and cards display clean total damage values without technical dice string notation.
4. **Baya Aranja (Oran Berry)**: Activates strictly when HP drops to 0 or below, preventing the faint and healing to 3 HP.
5. **Team & Storage Limit**: Personal board holds up to 4 monsters (active team of 3 + 1 reserve). Monster order can be rearranged anytime outside combat.
6. **Card Map Board**: Interconnected card node map. Starts with only Starting Town at (0, 0). Players hold up to 5 location cards in hand. Moving into an empty adjacent (+) slot allows placing a card from hand or a gym city from the top of the Cities Deck, discovering that zone.
7. **Cities & Shop**: Gym cities are kept in a separate deck, always plantable on any legal empty slot. Shop is strictly accessible while standing in a City node.
8. **River Shop**: Exactly 8 items displayed without duplicates. Buying an item immediately refills from the item deck without allowing duplicates.
9. **Luck System (🍀)**: Players can spend 1 Luck point to:
   - Add +1 to an attack dice roll in combat.
   - Draft 3 location cards from the environment deck and pick 1.
   - Redraw all 3 wild monsters during an encounter search.
10. **Gyms & Expansions**: Defeating gym 1 unlocks Tier 2 cards; gym 2 unlocks Tier 3; gym 3 unlocks Tier 4. Defeating 3 of the 4 available gyms triggers the Grand Tournament endgame.
11. **Codex**: Full in-game searchable compendium (Monsters, Attacks, Items, Areas).
12. **Game Reset**: Header button allowing quick reset and setup reconfiguration.

## Development & Deployment Workflow

### 1. Running Tests
Run the test suite whenever mechanics or data are modified:
```powershell
node c:\Dev\monster-journeys\test-suite.js
```
Ensure all 12 tests pass.

### 2. Building the Project
Bundle the modular files into `index.html`:
```powershell
node c:\Dev\monster-journeys\build.js
```

### 3. Local Testing Server
Start a local server if not already running:
```powershell
python -m http.server 3030 --directory c:\Dev\monster-journeys
```
Open `http://localhost:3030/` in browser.

### 4. Deploying to Production (GitHub & Vercel)
Always push changes to GitHub to trigger the automated Vercel production build:
```powershell
git add .
git commit -m "feat/fix: description"
git push origin main
```

## Agent Guidelines & Rules for Future Sessions
- **Always Push to GitHub (Vercel CI/CD)**: Always commit and push changes to GitHub (`git push origin main`) to trigger the Vercel production build after modifications.
- **Single-page Bundling**: Always edit files inside `js/`, `css/styles.css`, or `test-suite.js`, and run `node build.js` to compile into `index.html`.
- **Fail Fast**: Never use silent null guards or empty swallow catches. Throw loud errors if game state is invalid.
- **No Docstrings / Comments**: Do not write explanatory docstrings or documentation comments in code; write clean, self-descriptive code.
- **Do Not Run `dotnet build`**: This is a JS/HTML web project.
- **Tool Usage**: Do not use shell commands (`ls`, `dir`, `Get-ChildItem`) to explore files.
- **Git Ignore**: Graphify directories (`graphify-out/`, `.graphify/`) and Vercel folders (`.vercel/`) are ignored in `.gitignore`.
